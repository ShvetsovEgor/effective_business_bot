# Демонстрация и ручная проверка

[README](../README.md) · [Критерии оценки](PRODUCT.md) · [Сдача](SUBMISSION.md)

Это инструкция, а не отчёт о пройденной ручной приёмке. Ожидаемые результаты основаны на реализации; фактический результат на сдаваемом стенде нужно записать отдельно.

## Подготовка и тестовые данные

Запустить оба компонента по README и использовать отдельного тестового пользователя MAX. Для чистого сценария отправить `/reset` и подтвердить сброс только своих тестовых данных. Реальные персональные документы и реквизиты не нужны.

| Поле | Вымышленное значение |
| --- | --- |
| Идея | Хочу открыть кофейню с собой в Казани для сотрудников ближайших офисов |
| Форма / название / регион | ООО / Демо Кофе / `16` (Татарстан) |
| Годовой доход | `8000000` |
| Расходы за год, включая ФОТ, без отдельно вводимых взносов | `5000000` |
| Годовой ФОТ / сотрудники / основные средства | `1800000` / `2` / `1000000` |
| Взносы | `540000` — тестовое число, не расчёт реальной обязанности |
| Условия УСН, АУСН, отсутствие неучтённого НДС | Подтвердить как условия синтетического сценария, если бот спрашивает |
| Дата регистрации | `01.09.2026`; при проверке до этой даты выбрать прошедшую допустимую дату |
| Режим зарегистрированного ООО | УСН «Доходы» |
| Директор оформлен / персональные данные / расчёты с физлицами | Да / да / да |
| Кадровое событие | Нет — для проверки отсутствия автоматической задачи ЕФС-1 |

## Основной путь в MAX

| Шаг | Действие | Ожидаемый результат |
| --- | --- | --- |
| 1 | `/start`, ввести идею | Идея сохраняется, бот просит подтверждение. |
| 2 | Подтвердить и продолжить | Анализ обозначен как гипотезы без веб-поиска. При ожидании виден индикатор; извлечённые факты требуют подтверждения. |
| 3 | Выбрать ООО и ответить на вопросы | Сведения появляются в профиле, известные значения повторно не запрашиваются. |
| 4 | Во время ввода суммы спросить «Как выбрать ОКВЭД?» | Ответ по теме и возврат к тому же шагу; вопрос не записывается как финансовый параметр. |
| 5 | Закончить финансовые вопросы и открыть сравнение | Видны формулы, условия, причины ограничений. ОСНО и годовая АУСН «Доходы минус расходы» обозначены как неполные оценки. |
| 6 | Открыть «Как перейти?» и официальный источник | Условия перехода новой организации; без достаточных данных нет выдуманного точного дедлайна. |
| 7 | Выбрать режим и проверить план | Данные согласованы с профилем, доступны изменения до регистрации. |
| 8 | Выполнить первые два шага регистрации | Сохраняется прогресс, открывается следующий шаг. |
| 9 | `docker compose restart bot`, затем `/start` | Восстановлен незавершённый шаг, выполненные не потеряны. |
| 10 | Дойти до подачи документов | Требуется подтверждение действия пользователя; бот сам ничего не подаёт. На демо это только имитация в тестовом профиле. |
| 11 | Завершить тестовую регистрацию и заполнить профиль | Счёт, капитал, бухгалтерия и прочие задачи доступны параллельно. |
| 12 | «Мой профиль» → «Мои задачи», выполнить задачу | Она исчезает из активных и доступна в архиве с датой. |
| 13 | «Мой профиль» → «Документы» | Доступны три шаблона из `data/templates`; типовой устав открывает сервис ФНС. Полученные файлы остаются в переписке. |
| 14 | `/menu` → «Подобрать помещение» | Описание, ссылка на сайт и возврат в главное меню. |

## Короткий вход и контроль расчёта

`/menu` → «ООО уже зарегистрировано»: ввести данные из таблицы. Проверить задачи по ответам, официальные источники и сохранение выполненных общих задач после изменения профиля. Для регистрации `01.09.2026` календарное правило +4 месяца в коде даёт срок капитала `01.01.2027`. ЕФС-1 не должна появиться только из регистрации или числа сотрудников при отсутствии кадрового события.

Контроль УСН «Доходы» по базовой модели программы для тестовых параметров:

```text
Налог до вычета: 8 000 000 × 6% = 480 000 ₽
Вычет: min(540 000; 480 000 × 50%) = 240 000 ₽
Налог после вычета: 240 000 ₽
Налог + введённые взносы: 780 000 ₽
```

Это проверка реализации по заданным условиям, не подтверждение применимости режима реальной компании. При неизвестных взносах или неподтверждённых условиях полного сравнения быть не должно. Изменить сотрудников на `6`: АУСН недоступна с причиной. Изменить доход на `21000000`: точный победитель не объявляется, показано ограничение модели НДС.

## Сайт

1. Открыть [localhost](http://localhost/) для локального Docker-запуска. Кнопка бота ведёт на публичный домен, а не localhost.
2. Ввести: «Кофейня с собой, аренда до 250 тысяч, 40–90 м²».
3. Дождаться карты Казани и карточек из снимка; при достаточном числе подходящих записей — топ-5.
4. Открыть карточку: модельная экономика, конкуренты, статус анализа. Порядок адресов и задержка внешних API не фиксированы.
5. Раскрыть другие предложения и проверить переход к объявлению. Полная аналитика предназначена для топа.
6. Вне MAX отсутствие приветствия с именем допустимо. Его наличие внутри MAX само по себе не подтверждает серверную авторизацию.

## Устойчивость и протокол

| Проверка | Ожидание |
| --- | --- |
| Некорректная сумма или дата | Просьба исправить, сохранение этапа. |
| AI недоступен (отдельный тестовый стенд) | Понятное сообщение, сохранение локального маршрута без выдуманных фактов. |
| Старое нажатие кнопки | Актуальный экран, без повторного выполнения действия. |
| Остановка и запуск без удаления тома | Профиль и прогресс сохранены. |
| Вопрос за пределами базы знаний | Ограничение обозначено; непроверенный ответ не выдаётся за факт. |
| Сбой API сайта | Зафиксировать сообщение об ошибке; недоступная аналитика не считается успешной проверкой. |

После прогона записать: дату, commit hash, среду, версию Docker, доступ к боту, результаты шагов, время сборки и замечания. Протокол пока не заполнен. Предыдущие 50 автотестов не заменяют живую проверку MAX, сайта и Docker.
