# Геоаналитический модуль

Помогает предпринимателю в Казани выбрать помещение под аренду: по описанию бизнеса показывает места на карте, сравнивает поток, конкурентов и модельную экономику. Бот в MAX: **Хакатон МАХ 610**, `@t610_hakaton_max_bot`.

Модуль не заменяет просмотр помещения. Финансовые цифры — модель, не кассовый отчёт. Это написано в карточке места.

## Назначение

Сократить ручной обход объявлений, карт и новостей перед выбором точки. Пользователь описывает формат, бюджет и площадь обычным текстом и получает топ-5 объявлений аренды с Авито плюс список остальных подходящих.

## Основной пользовательский сценарий

1. Пользователь открывает виджет. Если страница открыта как мини-приложение MAX, MAX Bridge (`window.WebApp.initDataUnsafe.user`) показывает над полем поиска «Здравствуйте, имя». Вне MAX этой строки нет.
2. Вводит описание бизнеса и нажимает Enter или кнопку отправки. Поле уезжает влево вверх, открывается карта.
3. Сервер разбирает текст, отбирает объявления, считает поток и экономику, у десяти разных кварталов запрашивает конкурентов в Яндексе.
4. Слева появляются топ-5 карточек. Нажатие открывает справа аналитику: балл, экономику, конкурентов, пешеходов и вывод по новостям района.
5. Остальные подходящие объявления лежат в свёрнутом списке «Другие предложения». Нажатие переносит карту к точке и даёт ссылку на Авито. Полная аналитика справа — только у топ-5.

Чат-бот пока этот сценарий не выполняет: `/start`, `/help`, `/ping` и повтор присланного текста. Геоаналитика считается виджетом.

## Состав и архитектура

Один процесс `python -m yandex_map.server` отдаёт страницу и API.

- `yandex_map` — страница, карта и HTTP API.
- `analysis.brief` — текст бизнеса в JSON. Сначала Alice, при сбое — ключевые слова.
- `analysis.ranking` — отбор объявлений и итоговый балл: поток 10 %, поток без конкурентов 45 %, экономика 30 %, соответствие запросу 15 %.
- `analysis.footfall` — пешеходы в сутки из `yandex-geoanalytics-hexes.json` (H3, разрешение 7).
- `analysis.competitors` — организации Яндекса рядом с точкой. Ответ живёт в памяти и на диск не пишется.
- `analysis.finance` — модель «поток × аренда». Коэффициенты — допущения MVP.
- `analysis.insight` и `neurosearch` — новости по ближайшему пересечению улиц и вывод: подходит, осторожно или не брать.
- `commercial_sim.avito` — чтение снимка объявлений Авито.
- `bot.py` — отдельный процесс long polling к MAX. В основной запуск не входит.
- `commercial_sim.kazan` и `osm_food` — отдельные генераторы. Виджет их не вызывает.

## Запуск в Docker

Одна команда поднимает локальный компонент решения — виджет:

```bash
docker compose up --build
```

Ключи читаются из `.env` рядом с `compose.yaml` и в образ не копируются. Остановка и повторный запуск:

```bash
docker compose down
docker compose up --build
```

Бот подключается отдельно, когда сценарий в чате будет готов:

```bash
docker compose --profile bot up --build
```

Если у бота включён webhook, long polling не стартует и контейнер `bot` завершится. Виджет при этом продолжает работать.

Локально без Docker:

```bash
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
python3 -m yandex_map.server
```

## Параметры окружения и переменные

Имена без значений лежат в `.env.example`. Рабочий `.env` в git не входит.

| Переменная | Зачем |
| --- | --- |
| `API_ORG_SEARCH_YANDEX` | Поиск конкурентов. Без неё анализ мест не завершается. |
| `YANDEX_AI_STUDIO_API_KEY` | Alice: разбор запроса и вывод по месту. Нейропоиск новостей. |
| `YANDEX_CLOUD_API_KEY` | Замена ключа AI Studio, если задана она. |
| `YANDEX_CLOUD_FOLDER` | Каталог AI Studio. По умолчанию `b1gv2rfr13cpst5o42jr`. |
| `YANDEX_CLOUD_MODEL` | Модель. По умолчанию `aliceai-llm/latest`. |
| `GEOCODER_API_KEY` | Нужен только для повторного геокодирования снимка Авито (`python3 -m commercial_sim.avito`). В обычном запуске координаты уже лежат в JSON. |
| `MAX_BOT_TOKEN` | Только для контейнера `bot`. |
| `HOST` | Адрес сервера. Локально `127.0.0.1`, в контейнере `0.0.0.0`. |
| `PORT` | Порт сервера. Локально `8766`, в контейнере `80`. |

Уже заданная переменная окружения файлом `.env` не перезаписывается.

## Порты

- Docker: **80**. Страница http://127.0.0.1/.
- Локальный `python3 -m yandex_map.server`: **8766**. Страница http://127.0.0.1:8766/.
- У бота входящего порта нет: он сам ходит на `https://platform-api2.max.ru`.

## Зависимости

`requirements.txt`: `requests`, `h3`, `folium`, `openai`, `yandex-ai-studio-sdk`. Версии указаны нижней границей. Образ собирается из `python:3.12-slim`.

## Внешние сервисы и интеграции

Их нельзя поднять внутри Docker. Для проверки нужен интернет и ключи в `.env`.

- API Поиска по организациям Яндекса — конкуренты вокруг точки. Ключ ограничен сайтом `yandex.ru`, запрос уходит с заголовком `Referer`.
- Yandex AI Studio — разбор описания, новостная сводка и текстовый вывод.
- Overpass и Nominatim — ближайшее пересечение улиц для новости. Если Overpass не ответил, сводка идёт по улице и району без номера дома.
- Карты на странице — тайлы OpenFreeMap.
- Геокодер Яндекса в запросе пользователя не вызывается: координаты уже в снимке объявлений.
- Авито по сети не опрашивается. В репозитории лежит готовый снимок.

## Данные

- `avito-kazan-kommercheskaya-sdam.json` — объявления аренды коммерческих помещений Казани и координаты геокодера. Это источник выдачи виджета. Рядом лежит тот же снимок в CSV.
- `yandex-geoanalytics-hexes.json` — пешеходы и автомобили по гексагонам. Это выгрузка, не живой запрос.
- Экономика, потолок площади и балл считаются в `analysis` по допущениям. Лишние метры сверх формата не увеличивают число покупателей.
- `commercial_sim` — 29 вымышленных объявлений с полем `data_origin=simulated`. Виджет их не показывает. Команда `python3 -m commercial_sim` пишет их в `data/simulated/`.
- Ответы поиска организаций на диск не сохраняются.

## Проверка

1. Положить ключи в `.env` по образцу `.env.example`.
2. Выполнить `docker compose up --build`.
3. Открыть http://127.0.0.1/.
4. В поле на первом экране ввести: `Кофейня с собой, аренда до 250 тысяч, 40–90 м²`.
5. Нажать Enter.

Ожидаемое поведение:

- поле уезжает к боковой панели, видна карта Казани и тепловая карта потока;
- через некоторое время слева заголовок «Топ-5 из N объявлений» и пять карточек с адресами Авито;
- площади в топе сопоставимы с запросом, а не залы в сотни метров;
- под карточками свёрнута строка «Другие предложения»;
- клик по карточке топа открывает справа экономику, конкурентов и статус вывода;
- если Яндекс или нейропоиск недоступны, в статусе или в карточке виден текст ошибки, страница не падает;
- пустой запрос на первом экране ничего не отправляет.

Повторная проверка после `docker compose down` и снова `docker compose up --build` должна открыть ту же страницу.

## Ограничения

- География выдачи — Казань.
- Бот MAX не запускает подбор мест. Имя на первом экране есть только внутри мини-приложения MAX.
- Конкуренты — лучшие совпадения Яндекса в радиусе, не полный каталог города.
- Новости зависят от Overpass. Таймаут не кэшируется как удачный ответ.
- Финансовая модель не является прогнозом выручки.
- Сборка образа качает базовый образ Python и пакеты из `requirements.txt`. Сама установка зависимостей уложена в обычный `pip install` без лишних шагов.
