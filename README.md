# Навигатор ООО в MAX

MVP для хакатона MAX: помогает пройти регистрацию ООО, сохранить прогресс, определить ближайшие действия после регистрации и сравнить налоговые сценарии 2026 года. Всё работает по правилам и формулам. AI/LLM, внешних AI API и генерации юридических ответов нет.

## Быстрый запуск

Нужны **Node.js 22.13+** (рекомендуется 24 LTS) и npm. Используется встроенный `node:sqlite`, поэтому Node 20 не поддерживается; компилятор нативных модулей и отдельный сервер БД не нужны.

```sh
npm install
```

Создайте `.env` из `.env.example`:

```powershell
# Windows PowerShell — выполняйте, только если .env ещё не создан
Copy-Item .env.example .env
```

На Linux/macOS: `cp .env.example .env`. Вставьте токен **только в локальный `.env`**, после `MAX_BOT_TOKEN=`. Альтернатива — передать `MAX_BOT_TOKEN` через окружение процесса. Значение окружения имеет приоритет над `.env`.

`.env.example` содержит единственную строку `MAX_BOT_TOKEN=` без секрета. `.env`, другие локальные env-файлы, база, логи и сборка исключены из Git. Не вставляйте токен в исходники, README, команды с сохраняемой историей или коммиты. Токен, раскрытый в чате или другом публичном месте, замените в кабинете MAX.

```sh
npm run dev
```

Для сборки и обычного запуска:

```sh
npm run build
npm start
```

Откройте личный диалог с ботом в MAX и отправьте `/start`. Команды `/menu` и `/reset` зарегистрированы в MAX; сброс требует отдельного подтверждения. В группах финансовые данные не показываются.

База создаётся в `data/bot.sqlite` относительно рабочей директории. Не меняйте рабочую директорию между запусками. При необходимости задайте абсолютный `DATABASE_PATH` через окружение или локальный `.env`. Остановка — Ctrl+C. Запускайте один процесс на токен/базу. Сделать резервную копию проще после остановки процесса; при горячем копировании учитывайте SQLite WAL.

## Сценарии MVP

- Регистрация ООО: 10 коротких шагов, «Выполнено», пояснение, официальный источник и возврат к предыдущему шагу.
- Зарегистрированное ООО: название, дата, регион, режим, сотрудники, директор, персональные данные, расчёты с физлицами, отдельный вопрос о кадровом событии.
- Персональные задачи: базовые действия, ККТ, персональные данные и кадровый раздел по ответам. ЕФС-1 не появляется лишь из факта регистрации или наличия сотрудников.
- «Мои задачи»: выполненные задачи, ближайшие известные сроки, следующее действие, постраничный полный список, редактирование профиля.
- Статусы TODO, IN_PROGRESS, DONE, NOT_APPLICABLE. «В работе» и «Не применимо» доступны в подробностях пострегистрационной задачи. Изменение профиля сохраняет статус общих задач и скрывает исчезнувшие условные задачи.
- Анкеты и прогресс переживают перезапуск. Из `/menu` можно продолжить незавершённую анкету. Новое прохождение анкеты заменяет профиль только после последнего ответа.
- Калькулятор: УСН 6% и 15%, АУСН 8% и 20%, предварительная оценка ОСНО, формулы, условия применимости, ссылки.
- Переход новой организации на УСН/АУСН: правило 30 календарных дней от постановки на налоговый учёт, отдельный запрос этой даты, добавление задачи.

## Архитектура

```text
src/
  index.ts                    dotenv, база, запуск Long Polling
  bot/
    create-bot.ts             фабрика без запуска транспорта
    handlers/                 адаптер официального MAX SDK
    keyboards/                inline callback/link кнопки
    messages/                 транспортно-независимые экраны
  services/
    navigator.ts              маршруты экранов, сценарии
    forms.ts                  вопросы и проверка ввода
  domain/
    checklist/                типы и приоритет задач
    deadlines/                абсолютная дата, +дни, +месяцы
    tax/
      types.ts
      eligibility.ts
      calculators.ts
      transitions.ts
  data/
    llc-registration.ts
    llc-after-registration.ts
    tax-rules-2026.ts          ставки, лимиты, регионы, переходы
    sources.ts                официальные ссылки
  db/repository.ts            SQLite, транзакции, сохранение состояния
tests/                        расчёты, дедлайны, сценарии, MAX, перезапуск
```

Таблицы: `users` (в том числе сессия), `business_profiles`, `tasks`, `tax_calculations`, `processed_events`. Запросы параметризованы, задачи всегда ограничены MAX user_id. В `tasks` есть все поля из ТЗ, а также группа, порядок, активность и снимок правила. Создание схемы идемпотентно, версия — `PRAGMA user_version=1`.

Бизнес-правила не находятся в обработчиках MAX. Входящее событие обрабатывается транзакционно; кнопки связаны с конкретной версией экрана. Повторные callback не отмечают следующую задачу. Последние 500 событий на пользователя дедуплицируются в SQLite. Обработка и отправка сообщений одного пользователя идут последовательно. Профиль и расчёты не отправляются в сторонние сервисы; ответы доставляются через MAX.

Используется официальный `@maxhub/max-bot-api`, стандартный `bot.start()` с Long Polling. Перед стартом проверяется отсутствие webhook-подписок, чтобы SDK не отключил существующий webhook незаметно. Для будущего webhook можно использовать ту же `createBot()` и `bot.webhookCallback()`/`bot.start()` в режиме webhook, добавив HTTPS, секрет вебхука и обработку повторной доставки. HTTP-сервер в MVP не запускается.

Исходный `bot.py`, сертификаты и Python `Dockerfile` сохранены. Это прежний диагностический эхо-бот, **не запуск нового MVP**. Для MVP используйте команды npm выше. Не запускайте Python-бот и новый бот одновременно с одним токеном.

## Что именно считает налоговая модель

Год — **2026**, дата проверки конфигурации — **29.09.2026**. Регион вводится кодом ФНС (77 — Москва); полная таблица введения АУСН хранится со стартовыми датами. Отсутствие кода в таблице означает необходимость проверки, а не утверждение о законодательном запрете.

1. Доходы/расходы — сценарные годовые значения. Расходы **включают ФОТ, но исключают страховые взносы**. ФОТ повторно не вычитается. Для обычных режимов дополнительно спрашивается сумма взносов, уплаченных в пределах начисленных; иначе результат неполный. Пропуски никогда не выдаются за подтверждённый ноль.
2. УСН «Доходы»: `доход × ставка − min(взносы, налог до вычета × 50%)`; нагрузка — налог плюс взносы. Для ООО не применяется безлимитный вычет, предусмотренный в отдельных случаях для ИП.
3. УСН «Доходы − расходы»: `max((доход − расходы − взносы) × ставка, доход × 1%)`, база не ниже нуля. Убытки прошлых лет, торговый сбор, специальные льготы и особые операции не моделируются.
4. АУСН «Доходы»: `доход × 8% + 2 959 ₽` взносов на травматизм за полный год. АУСН «Доходы − расходы»: годовая оценка с минимумом 3% и взносами. **Налоговый период АУСН — месяц**, поэтому годовой расчёт Д−Р помечается неполным и не участвует в выборе минимального полностью рассчитанного варианта.
5. ОСНО: только ориентир налога на прибыль по ставке 25% и введённым расходам/взносам. НДС и отличия правил признания базы не рассчитаны; ОСНО не участвует в выборе минимума.
6. При доходе выше 20 млн ₽ точного сравнения MVP не делает и победителя не определяет. Для УСН нужно учитывать НДС; само по себе превышение 20 млн не означает потерю АУСН. Для меньшего дохода отдельно подтверждается отсутствие НДС по прошлогоднему доходу и специальных оснований/других налогов. УСН: лимиты доходов 490,5 млн, ОС 218 млн, сотрудников 130. АУСН: 60 млн, ОС 150 млн, сотрудников 5, введение в регионе.
7. Нечисловые условия режимов пользователь проверяет по официальной ссылке и подтверждает отдельно. Без подтверждения доступность и расчёт считаются неполными. Допущения действуют только для введённого сценария, не являются автоматической юридической проверкой бизнеса.
8. `regionalOverrides` предусматривает ставку и источник для региона/режима. Льготных ставок в начальном конфиге нет; UI явно предупреждает о базовой ставке. Суммы — оценка в рублях с точностью до копеек, не готовая налоговая декларация и не график платежей.
9. Минимум показывается **только среди полностью рассчитанных доступных вариантов в рамках модели**, без приблизительных ОСНО и АУСН Д−Р. Если для потенциально доступного УСН/АУСН «Доходы» не хватает данных, минимум не выбирается; для сравнения нужны хотя бы два полностью рассчитанных варианта. Это не рекомендация выбрать режим и не сравнение полной стоимости ведения бизнеса. Региональные льготы могут изменить вывод.

По одному годовому ФОТ нельзя корректно восстановить взносы по людям и месяцам, льготам и предельным базам. В частности, учтена необходимость проверки новой минимальной базы взносов за директора в 2026 году даже при отсутствии трудового оформления. В MVP взносы не угадываются.

НПД и ПСН для ООО не включены, ЕСХН за пределами MVP. Калькулятор не является юридической или бухгалтерской консультацией.

## Дедлайны и источники

Каждое правило содержит `source_url` и `verified_at`, задача — также `official_source_url`. Уставный капитал: регистрация +4 календарных месяца с корректным последним днём короткого месяца. Это предельный ориентир: решение/договор может предусматривать более ранний срок. Даты без достаточных исходных данных отображаются как «Нужно уточнить».

В переходах отдельно указана **дата постановки на налоговый учёт**. Рассчитывается ориентир +30 календарных дней, а юридический дедлайн оставлен «Нужно уточнить», поскольку перенос выходного/праздника требует актуального производственного календаря. Для действующих компаний переходы не выдумываются. По ЕФС-1 нет фиктивного срока от регистрации ООО.

## Проверки и демонстрация

```sh
npm run lint
npm run typecheck
npm test
npm run build
```

Тесты не требуют токена и не отправляют запросы в MAX. Они проверяют лимиты/минимальные налоги, вычет 50%, региональные overrides, календарные месяцы, условные задачи, полный сценарий, защиту данных, сброс, реальную SQLite и чтение прогресса из нового процесса Node. Адаптер проверяется через middleware официального SDK с замоканными сетевыми методами.

Для ручной приёмки: `/start` → регистрация → отметить два шага → остановить и снова запустить приложение → открыть регистрацию → убедиться, что показан третий шаг. Затем пройти анкету существующего ООО, калькулятор, «Как считается?», «Как перейти?» и официальный источник. Реальную доставку сообщений в MAX можно проверить только после локального задания рабочего токена.

## За пределами MVP

Webhook-развёртывание, фоновые напоминания/рассылки, производственный календарь, подача документов в государственные системы, полный кадровый/бухгалтерский учёт, точный НДС/ОСНО, помесячный АУСН Д−Р, автоматический расчёт страховых взносов, льготы по ОКВЭД и регионам, переходы действующих организаций, несколько ООО на пользователя, распределённое выполнение и административный интерфейс.
